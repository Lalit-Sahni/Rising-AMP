Breaks the whole thing

Three icons are inline SVG

HELMET_18, SHIELD and BRIEFCASE are real <svg> elements. Apple Mail, Gmail and Outlook all strip them. What is left is the container with nothing in it: the pale green square, the white square in the job card, the empty tile in the header.

Reads as unfinished

Default blue links

Some anchors set a colour and some do not, so the client paints the rest in browser blue and underlines them. Two blue links sit inside an orange brand.

Weak hierarchy

The job name appears three times

Once in the headline, once in the sentence under it, once in the card. Nothing is the hero, so the eye has nowhere to land before the button.

Alignment

Label left, value hard right

The detail rows leave a wide empty gutter and force long addresses to wrap against the right edge. It reads like a receipt, not an invitation.

Rules this markup follows

Hand this to the agent
RuleWhy, and what it replaced
No SVG anywhere Every client strips inline <svg>. The job tile is now the street number set as live text on a tint background, so there is nothing to strip. It also carries more information than a briefcase did.
No images at all Most clients block remote images until the reader allows them, so an image-built header shows as a grey box on first open. The wordmark is type. Nothing here needs downloading to be readable.
Tables and inline styles only No flex, no grid, no <style> block, no CSS variables. Outlook renders through Word and ignores all four.
Every anchor sets its own colour An <a> without an explicit color and text-decoration gets painted browser blue. Links here are #C64E12, which is the accent darkened to pass contrast on white.
Full-width button, padding on the anchor The padding sits on the <a>, not the cell, so the whole block is tappable. 15px vertical clears the 44px touch target on a phone.
Font stack, not a webfont Apple Mail will use Manrope if you serve it; Gmail will not. The stack falls back to the system face, and the layout is set in points that hold either way. No layout depends on Manrope's metrics.
Fluid 600 down to 320 One set of paddings works at both widths, so no media query is needed. Gmail's app ignores media queries, which is why the phone view is the same markup, not a variant.
Long addresses use word-break The recipient address stacks under its own label rather than being pushed right, so a 28 character address cannot blow out the row.
On the current one: the typography and spacing were already decent. It looked unprofessional for one reason, which is the two empty boxes, and those are a five minute fix. The rest of this is hierarchy: making the job name the thing you see first, and the button the thing you see second.
